# 검증: 실행한 것만 통과

## 1. 작업 단위마다

1. TASK.md 완료 조건 하나를 고른다. 테스트 이름이 없으면 먼저 정한다(`test_<조건>`).
2. 테스트를 쓰고 **실패하는 것을 먼저 확인**한다. 실패 출력 한 줄을 기록한다.
3. 구현한다. 수정 범위는 그 조건에 필요한 파일만.
4. 테스트를 실행해 통과를 확인한다. 기존 테스트도 함께 돌린다.
5. 결과 출력이 있으면 사용자가 볼 수 있게 경로와 요약 수치를 알린다(`HUMAN_CHECK`).
6. 커밋: `git add -A && git commit -m "<feat|fix|test>: <조건>"`
7. TASK.md 완료 조건 표의 상태를 갱신한다.

테스트 실행은 환경에 있는 것을 쓴다. pytest가 없으면 `python3 -m unittest discover -s tests -v`.

## 2. 반드시 넣을 경계 사례

과제와 관련 있는 것만 고른다.

- 빈 입력, 결측, 분모 0
- 기준값과 같은 값, 바로 아래, 바로 위
- 중복 키, 다중 매칭, 매칭 없음
- 시간 경계(자정, 기간 끝), 정렬되지 않은 입력
- 같은 입력을 두 번 넣었을 때 같은 출력(결정론)

## 3. 수치 검증

- 핵심 수치는 다른 방법으로 한 번 더 계산한다(라이브러리 vs `.hk/tools/metrics.py`, pandas vs 손계산 작은 표).
- 모델 성능이 기준선보다 크게 좋으면 누수 점검(`$hk-data` 4절)을 다시 한다.
- 제출 결과 파일은 형식(컬럼명, 행 수, 정렬, 인코딩)을 README 요구와 대조한다.

## 4. 독립 리뷰 (제출 30분 전, 사용자가 `리뷰`라고 하면)

새 세션이 가능하면 새 세션에서, 아니면 같은 세션에서 아래를 실행한다. **고치지 말고 목록만** 낸다.

```
지금까지의 대화를 신뢰하지 말고 처음 보는 리뷰어로서 이 폴더를 검토해.
기준: TASK.md 완료 조건과 README 요구사항.
찾을 것: 요구사항 누락, 검증 없이 PASS로 적힌 항목, 데이터 누수나 잘못된 분할,
경계값 처리, 실행 명령이 README와 다른 곳, 설명할 수 없는 코드.
각 항목은 심각도(높음/중간/낮음), 파일:줄, 근거 한 줄. 수정은 하지 마.
```

높음 항목만 고친다. 나머지는 DECISIONS.md 실패 지점에 기록한다.

## 5. 제출 전

```bash
python3 .hk/tools/preflight.py
```

- exit 0: 확인된 항목에 문제 없음. 정답 증명은 아니다.
- exit 1: 문제 있음. FAIL 항목을 고치거나 한계로 기록한다.
- exit 2: 검사한 항목이 0건. 통과로 읽지 않는다.
