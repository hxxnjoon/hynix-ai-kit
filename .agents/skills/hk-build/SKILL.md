# 서비스 구현: 얇게 끝까지, 로직과 화면 분리

## 1. 스택 고르기 (5분)

`python3 .hk/tools/preflight.py --env`로 있는 것을 확인하고 **이미 설치된 것 중 가장 단순한 것**을 고른다.

| 필요 | 우선 고려 | 다음 |
|---|---|---|
| 결과 표나 차트를 보여주기만 | 정적 HTML 파일 생성 + `python3 -m http.server 8000 --bind 0.0.0.0` | Streamlit (설치돼 있으면) |
| 입력을 받아 계산하고 결과 표시 | Flask 또는 FastAPI (설치된 쪽) | 표준 라이브러리 `http.server` |
| 여러 화면, 상태 저장 | Flask/FastAPI + SQLite(`sqlite3` 표준) | |

- 프레임워크나 빌드 도구(React, npm 프로젝트)는 요구사항이 명시하거나 사용자가 원할 때만 쓴다.
- 고른 이유와 버린 대안을 DECISIONS.md에 한 줄 남긴다.

## 2. 구조

```
core/      판정, 계산, 배정 로직. 순수 함수. 화면과 웹 프레임워크를 import하지 않는다
app.py     입력 받기 → core 호출 → 결과 표시. 로직을 여기에 쓰지 않는다
tests/     core 테스트(완료 조건), API 테스트(요청 → 응답)
```

- 핵심 로직이 core에 있어야 테스트로 검증되고 서술형에서 "이 결과는 어디서 계산되나"에 답할 수 있다.
- 담당자가 실제로 쓰는 말(설비명, 상태명)을 화면 문구에 그대로 쓴다.

## 3. 얇게 끝까지 (첫 완주)

1. 대표 입력 하나 → core → 화면에 결과 하나가 나오는 가장 짧은 경로를 만든다. 디자인은 나중이다.
2. 서버는 **반드시 `0.0.0.0`에 바인딩**한다. `localhost`만 쓰면 Browser 미리보기가 연결되지 않는다.
   - Flask: `app.run(host="0.0.0.0", port=8000)`
   - FastAPI: `uvicorn app:app --host 0.0.0.0 --port 8000`
   - Streamlit: `streamlit run app.py --server.address 0.0.0.0 --server.port 8000`
3. 서버는 별도 터미널 탭에서 실행하고 그 탭을 닫지 않는다. 사용자에게 **포트와 경로**를 알려 Browser 도구에 입력하게 한다.
4. 자동 확인: 서버를 띄운 상태에서 `curl -s http://127.0.0.1:8000/...`로 응답을 확인하거나, 프레임워크의 테스트 클라이언트로 API 테스트를 작성한다.
5. 커밋한다.

## 4. 확장

- 완료 조건 하나씩 core 테스트 → core 구현 → 화면 연결 순서로 진행한다(`$hk-verify`).
- 오류 상황(빈 입력, 잘못된 형식, 결과 없음)에서 화면이 무엇을 보여주는지 정하고 테스트한다. 조용히 실패하지 않는다.
- 요구사항에 없는 로그인, 권한, 설정 화면, 다국어를 만들지 않는다.

## 5. UAT 목록 (사람이 확인)

자동 검증이 끝난 뒤 마지막에 **한 번에** 준다. 중간에 하나씩 확인을 요청하지 않는다.

```
UAT-1  포트 8000 경로 /    조작: 샘플 파일 업로드      기대: 표 10행, 불량 2건 강조
UAT-2  포트 8000 경로 /    조작: 빈 파일 업로드        기대: "데이터가 없습니다" 안내
```

사용자가 Browser에서 확인하고 UAT별 PASS / FAIL과 관찰을 알려주면 TASK.md 완료 조건 상태에 `HUMAN_CHECK → PASS`로 반영한다. FAIL은 재현 후 고치고 해당 UAT만 다시 요청한다.

## 6. 제출 전

- README의 실행 명령으로 처음부터 다시 띄워 확인한다(설치되지 않은 패키지에 의존하지 않는지).
- 실행 중인 서버가 제출을 막는지 확인하고, 필요하면 종료 방법을 README에 적는다.
